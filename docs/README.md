# 文档索引

这个目录只放文档。改动记录按**日期**归档到 `reports/`，设计稿放 `plans/`，根下只留交接必读的那一份。

## 先看哪份

| 你的问题 | 看这里 |
|---|---|
| 我刚接手，现在是什么状态？ | [`交接文档.md`](交接文档.md) —— 现状、约束、红线、常用命令 |
| 某个功能为什么这么设计？ | [`reports/2026-09-18-项目现状分析.md`](reports/2026-09-18-项目现状分析.md) |
| 以前修过什么坑，别再踩 | [`reports/2026-09-18-遗留问题修复记录.md`](reports/2026-09-18-遗留问题修复记录.md) |
| 最近优化了什么、验证判据在哪 | [`reports/2026-11-01-性能与稳定性优化记录.md`](reports/2026-11-01-性能与稳定性优化记录.md) |
| 早期的设计/实现计划 | [`plans/`](plans/)（7 月产出，部分已过时） |
| 面向使用者的说明 | [`../README.md`](../README.md) |

## 目录约定

- `交接文档.md` —— 唯一长期维护的总览。**每次结束一轮工作都要更新它**（状态快照、约束、待办）。
- `reports/YYYY-MM-DD-主题.md` —— 一次工作的完整记录：改了什么、为什么、验证判据（可复跑的命令 + 期望输出）、刻意没做什么、下次注意点。**新建文件名必须带日期前缀**，否则看不出新旧。
- `plans/YYYY-MM-DD-主题.md` —— 动手前的设计稿。设计定型并被实现取代后不再改，保留作历史。

## 写作要求

- 判据必须**可复跑**（写命令，不写"已验证通过"这种结论）。
- 没做 / 没验证的，明确写「没做」「无法判定」，不要用"应该没问题"混过去。
- 涉及隐私的内容（日记正文、附件、凭据）不进文档。
