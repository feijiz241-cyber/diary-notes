## ① 日记切换日期丢失未保存内容（P1 / R2）

### 根因
`components/DayEditor.tsx` 的自动保存只依赖 600ms 防抖定时器，而 effect 的 cleanup 在**切换日期或卸载**时会 `clearTimeout`。用户在 600ms 内切走，定时器被清掉，最后一次输入永久丢失。

排查时还发现一个**更隐蔽的隐患**：切换日期的那一瞬间，`loaded` 仍是旧值、`entry` 还是旧日期的数据，若此时防抖 effect 重跑，会排出一个「把旧日期内容写到新日期」的定时器。当前实现只是靠 `setLoaded(false)` 触发的重渲染恰好清掉了它，属于**时序侥幸**，不是设计保证。

### 修复
- 引入 `dirty` ref 记录「有未保存改动」。
- 引入 `pending: { date, data }` **日期与草稿成对**的 ref，杜绝张冠李戴。
- 新增 flush effect：**切换日期或卸载时**若 `dirty` 为真，立即 `putEntry` 落盘。
- 用 `loadedFor === dateKey`（而不是布尔 `loaded`）判断「当前 entry 是否属于这一日期」，从根上堵住跨日期串写。
- 空内容不落盘（保持原有行为，避免凭空创建日记）。

### 验证
新增 `components/DayEditor.test.tsx`（mock 掉 TipTap，只测保存时机），3 个用例：
1. 输入后**立即卸载** → 标题已落盘（旧实现必失败）；
2. `rerender` 切到另一日期 → 旧日期内容落在旧日期，新日期**未被污染**；
3. 全空内容不落盘。

### 依赖与风险
- 无前置依赖。
- 风险：flush 是异步的，若用户**关掉整个浏览器标签**，最后一笔仍可能来不及发出（`beforeunload` 无法可靠等待异步请求）。这是所有防抖自动保存的固有限制，切页面/切日期已覆盖。

## ② 后端暴露到局域网（R1）

### 根因
`backend/index.mjs` 里 `server.listen(port, cb)` 未指定 host，Node 默认绑定**所有网卡**（实测 `0.0.0.0:5189` + `[::]:5189`）。加上后端**完全没有鉴权**，同一 Wi-Fi / 局域网内任何设备都能 `GET /api/entries` 读走全部日记、`POST` 写入、`DELETE` 清空。对一个「私人日记」应用，这是最需要优先处理的风险。

### 修复
- `createServer(store, port, host)`，默认 `HOST = process.env.HOST || '127.0.0.1'`，启动日志打印真实绑定地址。
- 需要跨设备访问时用 `HOST=0.0.0.0 npm run server` **显式**放开，README 中同时标注「无鉴权、风险自负」。
- 前端跟随改动：Vite 代理目标改为 `http://127.0.0.1:5189`，`start-diary.bat` 的后端探活也改为 `127.0.0.1`。

> 为什么必须写死 `127.0.0.1` 而不是留着 `localhost`：本机 `dns.lookup('localhost')` 在 verbatim 顺序下**优先返回 `::1`（IPv6）**。若后端只绑 IPv4 回环而客户端连 `::1`，就会出现连不上的假故障。

### 验证
- 单元测试新增：`createServer(store, 0).address().address === '127.0.0.1'`（防回归）。
- 冒烟脚本直接读 `server.address()`，输出 `绑定地址 = 127.0.0.1`。

### 依赖与风险
- **依赖**：②的「写死 127.0.0.1」是 ③④⑤ 后端改动的共同基础（同一文件、同一批提交），但不构成逻辑依赖。
- 风险：若用户此前把 `http://<本机IP>:5189` 收藏或分享给别人，升级后会失效——这正是预期行为。
- 残留：后端仍**没有鉴权**。只在用户主动 `HOST=0.0.0.0` 时有暴露面。

## ③ JSON 非原子写入（R4）

### 根因
`store._writeJSON` 直接 `fs.writeFile(file, ...)`：Node 会**先截断再写**。写操作虽在串行队列里，但**读操作不在队列中**，因此并发 `GET` 有机会读到被截断的半个文件；`_readJSON` 捕获解析异常后回退成 `[]`，表现为界面「瞬间全空」。数据量越大（如刚上传完附件），这个窗口越宽。

### 修复
- `_writeJSON` 改为**原子替换**：写同目录临时文件（`<file>.<pid>.<seq>.tmp`）→ `fs.rename` 覆盖目标；失败时清理临时文件。
- **关键补充**：Windows 上若目标文件正被并发读句柄占用，`fs.rename` 会抛 `EPERM`/`EBUSY`（首轮实现正是被这个打挂的）。因此增加 `_renameOver()` **退避重试**（最多 8 次、`10ms × i`）。重试期间读者只会看到完整的旧版或新版，不会看到半截内容。

### 验证
- `store.test.mjs` 新增 2 例：
  1. 写入后目录中**不残留 `.tmp`**；
  2. 「并发读永远不会瞬间变空」——先写入 50 条带 2KB 正文的基线（文件约 100KB 放大竞态窗口），一边 40 次写入、一边 150 次读取，断言读到的条数**从未低于基线 50**。
- **用例敏感性已实证**：用旧写法（直接 `writeFile`）跑同样的读写下，最小读到 **0 条**（成功抓到半截读取）；新写法恒为 50。

### 依赖与风险
- 无前置依赖。
- 风险：`rename` 在 Windows 上是「尽力而为的原子」；重试耗尽（极端磁盘/杀软占用）时会抛错并向上传播为 500，不会静默损坏数据——属于**宁可失败也不写坏**的取舍。

## ④ 附件生命周期：孤儿素材（P4）

### 根因
移除正文里的附件节点时只删了节点，**没有删服务端文件**（当初是刻意的：立刻删会让「撤销」变成死链）。代价是长期使用后 `files/` 里堆着无人引用的孤儿文件，且没有任何回收入口。图片有**完全相同的缺陷**。

### 修复
选择「**延迟回收**」而不是「删除即清理」，兼顾撤销安全与磁盘卫生：
- 后端：`/api/files`、`/api/images` 不带 `entryId` 时返回**全部**（新增 `listAllFiles` / `listAllImages`）。
- 前端 `lib/cleanup.ts`：`cleanupOrphanAssets()` 拉取全部日记 + 笔记 + 素材元数据，用 `editor-serialize.collectAssetIds()` 解析出文档里真正引用的 `imageId`/`fileId` 集合，**只删除不在集合内**的素材，返回删除/保留计数。
- 设置页新增「维护 → 清理未引用素材」，带二次确认弹窗（明确说明「仍被引用的不会被删除」）。

### 验证
新增 `lib/cleanup.test.ts` 3 个用例：
1. 4 个素材中 1 图 1 附件被引用 → 只删 2 个未被引用的，保留 2 个；
2. **笔记**里引用的附件同样被保留（覆盖跨日记/笔记的引用）；
3. 无任何内容时全部清空。
后端 `store.test.mjs` / `files.test.mjs` 覆盖 `listAllFiles` / `listAllImages`。

### 依赖与风险
- **依赖**：需要后端「列出全部」接口（同一提交内完成）。
- 风险：若某篇日记内容**保存失败**（内容未落盘但素材已上传），该素材会被判定为孤儿而删除。概率低，且弹窗已说明该操作不可恢复；建议清理前先导出备份。

## ⑤ 功能一致性（P2 / P3 / P6）

### P2 搜索不覆盖笔记
- **根因**：`lib/search.ts` 只遍历 `getAll()`（日记）；笔记虽然有独立的全文数据，却从未被检索。
- **修复**：保留 `searchEntries`（只搜日记，**森林页**仍用它按日期高亮树上的命中），新增 `searchAll` 同时搜日记 + 笔记，结果带 `kind` 字段。搜索页改用 `searchAll`，结果项显示「日记 / 笔记」标签；点笔记结果跳 `/notes?date=YYYY-MM-DD`。
- **配套**：`NotesPage` 支持 `?date=` 深链（初始化 + URL 变化时同步）。
- **验证**：`search.test.ts` 新增 2 例——`searchAll('旅行')` 同时命中日记与笔记且 `kind` 正确；`searchEntries` 仍**只**返回日记。

### P3 清空粒度与文案不符
- **根因**：`DELETE /api/entries` 走 `store.clearAll()`，**同时删掉日记 + 全部图片 + 全部附件**，但不删笔记；而按钮文案写的是「清空全部日记」「删除全部日记与图片」，与实际行为和「笔记仍在引用这些素材」的事实都不符。
- **修复**：
  - 语义拆分：`clearEntries()`（**只清日记条目**，不动素材）/ `clearAllData()`（日记 + 笔记 + 图片 + 附件，全量重置）。
  - 路由：`DELETE /api/entries` → 只清日记；新增 `DELETE /api/data` → 全量重置（供「还原备份」使用）。
  - UI：危险区域拆成「清空全部日记」「清空全部笔记」两个独立确认框，文案与实际行为一致，并提示「图片与附件不会被连带删除，可用维护功能回收」。
  - 顺带修掉 R3 的主要触发路径：**清空日记不再破坏同日笔记引用的素材**。
- **验证**：后端新增「清空粒度」HTTP 用例（清日记后笔记仍在）；`files.test.mjs` 覆盖 `clearEntries` 不删素材、`clearAllData` 全清；冒烟脚本实测 `清空日记 → 0 / 1 / 1`、`全量重置 → 0 / 0`。

### P6 无兜底路由
- **修复**：新增 `pages/NotFoundPage.tsx` 与 `<Route path="*">`，顺手修正 `App.tsx` 里不一致的缩进。

## ⑥ 部署配置与文档（P5 / P9）

### P5 部署配置误导
- **根因**：仓库里放着 `vercel.json` / `netlify.toml`（含 SPA 回退），会让人以为能一键上线。实际上后端是常驻进程 + 本机文件存储，部署后 `/api` 会被 SPA 回退成 `index.html`，前端拿到 HTML 解析 JSON 失败、功能全废，且数据无处落盘。
- **修复**：**删除** `vercel.json` 与 `netlify.toml`，在 README 顶部用独立小节写明「仅支持本机运行」及原因。删除是 git 可逆的（`git revert 2915886`）。

### P9 文档过期
- **修复**：README 补齐笔记 / 附件 / 森林 / 搜索范围 / 清理素材等功能点，更新目录结构（补 `lib/cleanup`、`NotFound`、`files/` 等），补充「仅本机运行」「`HOST` 放开的风险」「素材按日期归属且日记与笔记共用」等关键约定。

## 未处理项与后续建议

1. **P7 首屏主题闪烁（FOUC）**——`.dark` 在 `useEffect` 里才挂载。修法是在 `index.html` 加一段内联脚本，在首帧前读 `localStorage` 并设置 `documentElement.classList`。
2. **R3 残留**——`deleteById` 仍会按日期连带删除图片与附件。当前**没有 UI 入口**可删除单篇日记（`deleteEntry` 只被测试引用），所以不可达；一旦将来加「删除这天日记」按钮，需要先改为不连带删除素材。
3. **R6 上传体积**——前端限 20MB，后端 `readBody` 未校验大小、无请求体上限，属可加固项。
4. **R7 性能**——保存与搜索均为全量读写 JSON，个人数据量下无感，量级上去需引入索引或分页。
5. **依赖瘦身**——`dexie` / `fake-indexeddb` 仅为旧 IndexedDB 一次性迁移保留，可评估是否下线迁移功能后移除。
