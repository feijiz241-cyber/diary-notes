## 一、总览

一个**本地优先（local-first）的个人日记 + 笔记应用**。前端是跑在浏览器里的单页应用，数据通过同机的一个常驻 Node 进程落到硬盘文件（`backend/data/`），**不依赖数据库、不联网、不上传任何服务器**。

设计目标非常明确：给非技术用户一个「双击 `start-diary.bat` 就能用」的私人写作工具，且**数据不会因为清浏览器缓存而丢失**——这一点从提交历史能看出演进脉络：最早数据存在浏览器 IndexedDB，后来专门做了一次「本地后端 + 文件落盘」的重构（`cd856f7` → `b607b51`）。

代码量约 **4400 行**（含测试），规模上是「单人可维护的小型全栈应用」，当前功能完整、可日常使用。

## 五、数据模型与存储布局

| 数据 | 文件 | 主键 | 备注 |
|---|---|---|---|
| 日记 | `diary.json` | `date`（一天一篇，upsert 覆盖） | 含 title / TipTap content / mood / tags |
| 笔记 | `notes.json` | `id`（uuid，一天可多篇） | 与日记**完全独立存储** |
| 图片 | `images/<id>.<ext>` + `manifest.json` | `imageId` | manifest: `{ entryId, ext, type }` |
| 附件 | `files/<id>.<ext>` + `manifest.json` | `fileId` | manifest: `{ entryId, ext, name, type, size }` |

**核心约定：`entryId` = 日期字符串 `YYYY-MM-DD`。**
也就是说，图片和附件**不是**挂在某篇日记/笔记上，而是挂在「这一天」上 —— 同一天的日记和笔记**共用同一个图片/附件池**。这个简化让关联查询变得极简单，但也带来副作用（见风险 R3）。

内容格式统一为 **TipTap JSON**；图片以 `file:<id>` 作 src 并带 `imageId/entryId` 属性，附件以 `fileAttachment` 原子节点带 `fileId/entryId/name/size/mime`。

## 六、已实现的功能

**日记（Today / Day/:date）**
- 一天一篇，富文本编辑：加粗、斜体、H2、有序/无序列表、引用、行内代码
- 标题、心情 emoji（MoodPicker）、标签（TagInput）
- 600ms 防抖自动保存，显示「已自动保存」

**笔记（/notes）**
- 一天可多篇，与日记互不影响
- 每篇独立卡片，自动保存 + **卸载时 flush**（防止切日期丢内容）
- 年历查找模式：按需展开、整年 12 个月平铺、有笔记的日期木板色高亮、点日期跳转后自动收起

**图片与附件**
- 图片：工具栏按钮上传，内嵌渲染（通过 blob URL）
- 附件：工具栏**回形针按钮**上传**任意类型文件**（多选，20MB 上限），插入可下载的附件卡片（文件名 + 大小 + 下载 + 移除）
- 附件下载接口带 `Content-Disposition`，中文文件名正确处理

**森林（/forest）**
- 把当月日记可视化为像素树（`MonthTree` + `tree-layout` 布局算法）
- 点树叶弹出预览（`LeafPreview`），显示与前后篇的间隔天数，可跳转编辑
- 内置搜索框，命中的日期在树上高亮

**日历（/calendar）**
- 全年 12 个月视图，有日记的日期显示心情 emoji，点击直达当天

**搜索（/search）**
- 标题 + 正文全文检索（不区分大小写），带上下文片段

**设置（/settings）**
- 浅色/深色主题切换（记忆偏好，跟随系统）
- 导出 JSON 备份 / 导出 Markdown
- 导入备份还原（entries + notes + images + files，保留原 id）
- 检测并迁移旧版浏览器 IndexedDB 数据
- 危险区：清空全部日记

**其他**
- 移动端优先响应式（桌面侧边栏 / 移动端底部导航）
- 65 个单元测试覆盖数据层、存储层、HTTP 路由与关键组件

## 八、关键设计决策（与权衡）

1. **本地优先 + 文件落盘，而非 IndexedDB**
   *为什么*：浏览器存储会被清缓存/换浏览器清掉。
   *代价*：必须有常驻后端进程；无法部署到 Vercel/Netlify 这类无状态平台。

2. **零依赖后端（只用 `node:http`）**
   *为什么*：给非技术用户减少安装/依赖故障面，`npm install` 后即可跑。
   *代价*：路由、请求体解析、静态服务、上传下载全部手写；缺少成熟框架的中间件（如体积限制、鉴权、CORS）。

3. **以「日期」作为资源的关联键（entryId = YYYY-MM-DD）**
   *为什么*：日记一天一篇、笔记挂在日期上，查询和清理极简单（一天的所有素材一把抓）。
   *代价*：日记与笔记共享池，语义上「一篇日记的附件」不成立；删除日记会波及同日笔记（R3）。

4. **单一串行写队列（`_writeChain`）**
   *为什么*：无数据库，多个写请求若并发读改写同一个 JSON 会互相覆盖。
   *代价*：所有写（含大附件 base64）严格排队，吞吐受限；且**队列内不能再调用会入队的方法**，否则死锁 —— 这是项目里最容易踩的坑（已拆出 `_rmFilesByEntry` / `_clearAllFiles` 等内部方法规避）。

5. **TipTap JSON 作为内容格式**
   *为什么*：结构完整、可无损还原、便于遍历提取文本（搜索/导出）。
   *代价*：不可读、需要迁移策略（版本号），且富文本渲染依赖自定义 NodeView。

6. **防抖自动保存 + 乐观更新**
   *为什么*：写作场景无「保存」按钮，体验更顺。
   *代价*：需要显式处理卸载/切页时的落盘（笔记已补 flush，日记待补 → P1）。

7. **备份 = 单个 JSON（图片/附件以 base64 内联）**
   *为什么*：一个文件即完整快照，导入导出简单。
   *代价*：备份体积膨胀约 33%；大附件多时导出/导入慢且吃内存。

## 九、潜在风险（按优先级）

**R1（高）｜局域网内零鉴权暴露**
`server.listen(port)` 未指定 host，实测监听在 `0.0.0.0:5189`，且全站**无鉴权、无 CORS 限制**。同一 Wi-Fi/局域网内的任何设备都能 `GET /api/entries` 读走全部日记、`POST /api/files` 写入、`DELETE` 清空。对「私人日记」这是最需要处理的风险。最小改动：监听改为 `127.0.0.1`。

**R2（高）｜日记丢编辑（P1 的后果）**
快速切换日期/离开页面会丢失最后一次输入，且**行为与笔记不一致**（笔记已修）。这是用户可直接感知的数据丢失。

**R3（中）｜共享资源池的连带删除**
`DELETE /api/entries/:id` 会按 `entryId`（=日期）删掉该天所有图片与附件。若同一天的**笔记**引用了这些附件，笔记里的附件卡片会变成死链。图片同理（历史遗留）。

**R4（中）｜非原子写入**
`store._writeJSON` 直接 `fs.writeFile`（截断后写入），而读操作**不在**串行队列里。理论上并发时 `GET` 可能读到半截 JSON → `_readJSON` 捕获后回退成 `[]`，表现为界面瞬间「空数据」。改为「写临时文件 + `rename`」即可消除。

**R5（中）｜部署幻觉**
仓库里的 `vercel.json` / `netlify.toml` 会让人以为能一键上线，实际部署后 `/api` 被 SPA 回退成 HTML，前端解析 JSON 失败、应用不可用，且**数据无处可写**。应删除或改成明确警示。

**R6（中）｜上传无服务端体积限制**
前端限 20MB，但后端 `readBody` 只做字符串累加、无上限；base64 再放大 ~33%。异常/恶意请求可造成内存尖峰（`content-length` 也未被校验）。

**R7（低）｜性能天花板**
每次保存/搜索都全量读写整个 JSON（`readAll`/`readNotes`），无索引、无分页；搜索每次都要遍历所有日记并做 `docToText`。个人几千篇内无感，量级上去会线性变慢。

**R8（低）｜可用性细节**
FOUC、无 404 路由、README 过期、清空文案与实际不符、附件上传失败仅有 `alert`。

## 十、改进建议（按投入产出排序）

1. **日记补上卸载 flush** —— 直接复用 `NotesPage.NoteCard` 里已验证的做法（`dirty` ref + 卸载时立即 `putEntry`），约 15 行，消除真实的数据丢失。
2. **后端默认只监听 `127.0.0.1`** —— 一行改动，关掉最大的隐私风险；如确有跨设备需求，在 README 里显式说明如何开启。
3. **写入改原子**（写 `.tmp` 再 `rename`）—— 消除 R4 的读取窗口。
4. **附件生命周期收口** —— 移除节点时调 `deleteFile`，或提供一个「清理无引用附件」的维护按钮。
5. **一致性补齐** —— 搜索纳入笔记；「清空」区分日记/笔记并修正文案；补充 404 路由。
6. **清理部署误导** —— 删除 `vercel.json`/`netlify.toml`，或在 README 顶部用醒目段落说明「仅支持本地运行」。
