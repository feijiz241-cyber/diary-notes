## 一、项目是什么

**本地优先的个人日记 + 笔记应用**。React 单页应用跑在浏览器，数据由同机常驻 Node 进程落盘到 `backend/data/`，**不联网、不上传、不受清缓存影响**。视觉上是一套完整的**「我的世界 2D 像素材质」主题**。

- 规模：约 4400 行（含测试），frontend 33 个源文件 + backend 6 个，54+ 次提交
- **明确不做联网部署**（部署配置已删除，README 已声明）
- 用户是**非专业开发者**，诉求是「双击就能用」

## 四、🎨 视觉主题系统（改 UI 前必读）

`frontend/src/index.css` 定义了一套完整的 **「我的世界 2D 像素材质」** 主题，浅色=明亮户外、深色=洞穴。这是全应用的视觉基调，**任何新 UI 都必须遵守**：

- **全局无圆角**：`--radius: 0rem`，且 Tailwind 的 `--radius-lg/md/sm/xl` 全部映射为 0 → `rounded-lg` 等类实际无效
- **材质工具类**（`@layer utilities`）：`mc-stone`（石头按钮）、`mc-plank`（木板）、`mc-sign`（木牌标题）、`mc-anvil`（铁砧金属弹窗）、`mc-dirt`（泥土底）、`pixel-shadow/-sm/-lg`（硬像素投影）、`pixel-press`（按下位移）
- **描边**：一律 `2px solid var(--mc-outline)`（浅色深棕 `#2a1d10`，深色浅棕 `#b08d5f`）
- **文字色**：材质底上写死 `text-[#2a1c0d]`（深棕）或 `#f4f4f4`（金属上白字）
- **阴影写法陷阱**：Tailwind 任意值里 `var(--mc-outline)` 括号必须严格配对。**历史上曾有 4 处多写一个 `)` 导致阴影类整体失效**（导航、弹窗、气泡）——已修复，新增类名时务必注意
- 编辑器排版（`.tiptap h1/p/ul/blockquote/code/img`）也在此文件定制
- 心情色板在 `lib/mood.ts`：8 种心情，每种带 emoji/label/**马卡龙色**（森林叶子按此着色）

## 六、后端 API 全表（实测核对）

| 方法 & 路径 | 行为 |
|---|---|
| `GET /api/entries?year=&month=` | 列日记，可按年/月过滤 |
| `GET /api/entries/:date` | 按日期取一篇（404 若无） |
| `GET /api/entries/id/:id` | 按 id 取 |
| `PUT /api/entries` | 按 date upsert（一天一篇） |
| `DELETE /api/entries` | **只清日记条目**，不动素材（`clearEntries`） |
| `DELETE /api/entries/:id` | 删单篇日记，**会连带删该日期的图片+附件**（UI 无入口） |
| `GET /api/notes?date=` | 列笔记（不带 date 返回全部） |
| `PUT /api/notes` | 有 id 更新，无 id 新建 |
| `DELETE /api/notes` / `DELETE /api/notes/:id` | 清空 / 删单篇 |
| `GET /api/files?entryId=` | 列附件元数据；**不带 entryId 返回全部** |
| `GET /api/files/:id` | 下载（`Content-Disposition`，中文文件名用 `filename*=UTF-8''`） |
| `POST /api/files` | base64 上传（fileId/entryId/ext/name/type/size/base64） |
| `DELETE /api/files` / `DELETE /api/files/:id` | 清空 / 删单个 |
| `GET /api/images?entryId=` / `:id` / `POST` / `DELETE` | 同附件模式；`:id` 直接回二进制 |
| `DELETE /api/data` | **全量重置**（日记+笔记+图片+附件），供"还原备份" |
| `GET /api/export` | entries + notes + files manifest（前端导出实际不走它） |
| `POST /api/import` | 按 entries/notes/files 逐条 upsert |
| 其余 | 404；异常统一 500 |

**注意**：`readBody()` 会把 JSON 解析失败**静默**成 `{}`（不报错）；`putImage`/`putFile` 写二进制用的是普通 `fs.writeFile`，**不是原子写**（只有 JSON 走 `_writeJSON`）。

## 七、数据布局与素材生命周期

```
backend/data/
├─ diary.json        Entry[]：{ id, date, title, content(TipTap JSON), mood, tags, createdAt, updatedAt }
├─ notes.json        Note[] ：{ id, date, title, content, createdAt, updatedAt }（一天可多篇）
├─ images/<id>.<ext> + images/manifest.json   { id: { entryId, ext, type } }
└─ files/<id>.<ext>  + files/manifest.json    { id: { entryId, ext, name, type, size } }
```

- **`entryId` = 日期字符串 `YYYY-MM-DD`**：同一天的日记与笔记**共用**同一个素材池（删素材要看日期，不能只看某一篇）
- **移除即删**：`Editor.onUpdate` → `asset-sync.snapshotAssets` 前后 diff → `purgeRemovedAssets` 立即 `DELETE` 被移出正文的素材
- **撤销陷阱**：移除后 `Ctrl+Z` 会恢复卡片但文件已删 → 失效卡片（用户已明确接受此取舍）
- **孤儿素材兜底**：设置 → 维护 → 清理未引用素材（`cleanup.ts`，全库扫描比对引用）
- 导入备份用 `clearAll()`（= `DELETE /api/data`）全量重置后按原 id 还原

## 八、⚠️ 关键约定与坑位（14 条）

1. **改后端必须重启进程**；前端 Vite 会 HMR。用户常忘重启 → 新 API 404。
2. **`store._enqueue` 串行写队列内不能再调用会入队的公共方法**（死锁）。必须用 `_xxx` 无入队内部版本（现有 `_rmFilesByEntry` / `_clearAllFiles` / `_clearAllImages`）。
3. **JSON 写入是原子的**（`.tmp` + `rename`），且 Windows 下目标被读句柄占用会抛 `EPERM/EBUSY` → 必须走 `_renameOver` 退避重试，**别"简化"掉**。
4. **React 19 StrictMode**：开发期每个 effect 挂载即跑两次。所有副作用（保存、fetch、删除）都要幂等。
5. **`setContent(value, false)` 不触发 onUpdate** —— "移除即删"机制成立的前提，**别改成 `true`**，否则切换日期会误删素材。
6. **`Editor` 的外部 value 同步靠 `JSON.stringify` 深比较**，大文档下有性能成本，别在 onChange 里塞大对象。
7. **Tailwind v4 任意值类名括号必须配对**（曾有 4 处多一个 `)` 导致阴影类失效）。写 `shadow-[...]`、`bg-[var(--x)]` 时务必核对。
8. **主题是硬约束**：全局 `--radius: 0`、2px 描边、硬像素投影。新增 UI 用现成 `mc-*` 工具类，别引入圆角/柔和阴影。
9. **后端默认 `127.0.0.1`**（`HOST` 可放开）。本机 `localhost` **优先解析 `::1`** → Vite 代理与 bat 后端探活写死 `127.0.0.1`；前端探活仍用 `localhost`（Vite 绑 `::1`）。
10. **dev server 的 `no-store` + `cacheDir: .vite-dev` 别动**，治浏览器 `ERR_CACHE_READ_FAILURE` 白屏的。
11. **curl 测本机必须 `--noproxy '*'`**，否则走代理 502，会误判服务挂了。
12. **改路由要同步改 `test/mockApi.ts`**，否则前端测试与真实行为脱节。
13. `AppShell` 的 `<main>` 限宽 `max-w-3xl`(768px)，而日历/笔记年历是 `xl:grid-cols-3` → **桌面端 12 个月排 3 列会偏挤**（已知布局问题 P8）。
14. 提交信息用**中文 conventional commit**；Node 用托管路径 `C:\Users\quan\.workbuddy\binaries\node\versions\22.22.2-2\node.exe`。
